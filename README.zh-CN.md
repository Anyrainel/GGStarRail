## 它能做什么

- **整理遗器**：根据仓库和配装目标，找出值得保留、需要复核或可考虑分解的遗器。
- **评估角色练度**：为单件遗器和当前配装评分，检查缺失部位、套装效果和主词条是否达标。
- **规划角色配装**：选择隧洞遗器与位面饰品套装、设置词条偏好，并从仓库中寻找合适的装备。
- **规划资源投入**：查看遗器强化、合成和变量骰子的候选建议。
- **设置个人优先级**：用自己的榜单整理角色、光锥和遗器套装。
- **快速查资料**：用中文或英文浏览角色、光锥、遗器套装和成就资料。

## 从这里开始

- **导入账号数据**：在账号数据页导入支持的扫描器 JSON 文件，或通过 UID 导入公开展柜。
- **配置角色配装**：在配装页设置目标套装、主词条和评分权重。
- **查看当前装备**：在账号数据页查看角色配装并浏览仓库。
- **寻找值得保留或投入的遗器**：在遗器整理和资源页查看建议。

## 工具

### 账号数据

用导入的账号数据查看装备，决定下一步优先提升什么。

- 查看已拥有角色、养成进度、星魂、行迹和当前装备。
- 按属性和状态筛选光锥、隧洞遗器和位面饰品。
- 查看遗器评分，以及当前装备与配装目标的匹配情况。
- 寻找值得强化的遗器、适合定向合成的配装缺口，以及可考虑使用变量骰子的遗器。
- 将遗器分为保留、复核和分解复核，并保护已装备、已锁定或状态不明的部件。
- 预览并导出供 GOODScanner 管理器使用的锁定与弃置标记指令。

### 配装

为每个角色设置目标装备，并寻找符合要求的部件。

- 配置隧洞遗器四件套与位面饰品两件套，也可使用隧洞遗器 2+2 组合。
- 设置躯干、脚部、位面球和连结绳的主词条偏好。
- 自定义遗器评分的副词条权重和评级门槛。
- 根据配装目标生成六个部位的筛选条件。
- 按自己的评分偏好，比较已导入仓库中符合条件的装备。

### 榜单

维护个人优先级列表，辅助账号规划。

- 按属性排列角色。
- 按命途整理光锥。
- 按定位和个人偏好排列隧洞遗器与位面饰品套装。

### 图鉴

不用切到其他资料站，也能浏览游戏资料。

- 角色技能、属性、星魂、行迹和养成材料。
- 光锥效果、叠影等级、属性和养成材料。
- 隧洞遗器与位面饰品的部件和套装效果。
- 成就搜索、分类筛选，以及导入或手动记录的完成进度。

## 导入与数据说明

- 支持 GGStarRail、GOODScanner HSR、Reliquary、HSR-Scanner、Kel 和 Fribbels v4 JSON 文件，导入前可先审阅内容。
- 完整仓库流程需要包含未装备物品的扫描或抓包导出文件。
- Enka / MiHoMo UID 导入只包含公开展柜角色及其装备。为同一账号补充导入这些数据时，会保留此前已导入的更完整仓库数据。
- 也提供 HoYoLAB / 米游社导入入口，用于获取角色列表及已装备物品。此方式需要自行提供 Cookie，目前尚未完成真实账号导入的全流程验证。如遇账号验证，需要在官方应用或网站中完成。
- 应用数据保存在当前浏览器中，暂不支持云备份。导入用的 Cookie 仅用于当次请求，不会保存。
- 遗器评分取决于你设置的词条权重。目前不提供队伍伤害计算或以队伍伤害为目标的配装优化。
- 遗器整理提供建议和扫描器指令；网站本身不会修改游戏内物品。

## 本地开发

```bash
npm ci
npm run data:restore
npm run assets:webp
npm run dev
```

`data:restore` 会下载并校验当前提交指定的数据与图片资源，全新检出无需本地 GIlore 仓库。

常用命令：

- `npm run check` 运行完整校验，包括测试和生产构建。
- `npm run dev:worker` 启动本地账号导入 Worker。
- `npm run demo:start` 在端口 41737 启动或复用独立于终端的演示站（Windows/PowerShell）。

部署与数据维护见[托管与数据更新](docs/deployment.md)，数据来源见[来源说明](docs/source-provenance.md)，导入细节见[账号导入](docs/account-imports.md)和[安全说明](docs/security.md)。
